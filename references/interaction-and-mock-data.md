# 交互与 Mock 数据

## Mock 边界

- 所有请求数据、列表、详情、用户信息和操作结果都来自原型内的 mock fixture 或内存状态。
- 可以参考已有接口字段和类型命名，但在原型中明确标注“mock”，不宣称已接通后端。
- 表单提交、保存、删除、审批等动作只能更新内存状态、切换页面或显示反馈。
- 不调用真实的 POST、PUT、PATCH、DELETE 接口，不写数据库、文件或浏览器持久化存储。
- 如果需求必须展示接口失败或权限差异，用可复现的本地状态开关模拟，不伪造真实运行证据。

## 交互覆盖

至少实现需求明确的核心操作：

- 页面主导航、返回和必要的页面跳转。
- 表单输入、校验提示和提交后的可观察结果。
- 搜索、筛选、排序或分页（需求涉及时）。
- 弹窗、抽屉、详情查看和取消操作（需求涉及时）。
- 空数据、初始数据和操作后的状态（需求涉及时）。

每个状态应有清晰的页面反馈。没有需求依据时，不额外增加复杂错误体系、重试策略或防御性流程。

## 数据设计

Mock 数据应：

- 覆盖页面默认展示所需字段。
- 使用容易辨认且不含真实敏感信息的示例值。
- 让用户可以重复操作并观察状态变化。
- 与项目可见接口契约保持字段名称和基本类型一致；无法确认时标注假设。

## 原型标识

页面中或入口附近明确标识 prototype/mock，避免评审者把示例数据或临时行为当作正式能力。
