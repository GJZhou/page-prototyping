# 项目集成与原型落盘

## 受限项目检查

先读取能快速说明项目表面的文件：

- 根目录 README、包管理和构建文件。
- 路由入口或页面目录的直接清单。
- 附近页面的入口文件。
- 组件库、样式配置和设计令牌配置。
- 项目已有的开发启动命令。

不递归检索无关源码，不为一个页面原型分析整个项目调用链。优先遵循项目中的 `AGENTS.md` 和已有目录约定。

## 宿主选择

1. 如果需求对应已有页面或业务流程，优先在该页面上下文中加入临时 prototype 入口。
2. 使用查询参数、开发环境开关或项目既有的临时路由机制，使 prototype 不成为默认生产路径。
3. 如果没有合理的宿主页面，在项目根目录创建 `prototype/`，并按页面或流程建立清晰的子目录。
4. 如果项目没有可识别的前端框架，生成自包含的 HTML/CSS/JavaScript 文件和最短启动说明。

## 修改边界

- 原型文件必须有明显的 prototype 标识，避免被误认为正式页面。
- 优先复用现有组件和样式，不复制一套新的生产设计系统。
- 不修改数据库、后端接口、权限配置、系统配置或生产构建入口。
- 新增依赖、修改公共路由或修改已有生产组件前，先说明影响并取得用户确认。
- 原型运行所需的 mock 数据和临时状态放在原型边界内，不写入生产存储。

## 无法识别技术栈

如果只能确认项目是代码仓库但无法确认前端运行方式，先说明证据不足。只有用户接受独立临时原型时，才使用自包含 HTML；不得猜测一个框架并改写项目入口。
